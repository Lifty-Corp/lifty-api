# Lifty Slack app configuration

`lifty.manifest.json` is the checked-in configuration reference for the shared
Lifty Slack app. This API owns its maintenance because it owns hosted Slack
authorization. The manifest is not read by the API build or deployed
automatically; compare it with the Slack app console before applying a change.
Moving this file does not change the live Slack app.

Keep all three redirect URLs until their corresponding integrations and
in-flight authorizations have been explicitly retired. The Integromat redirect,
Events API and interactivity settings also serve existing internal workflows.
Production and staging share the app; its interactivity URL remains the
production Functions ingress, which routes staging interactions by environment.

## Customer authorization

Use a workspace-scoped link generated by the API. Customer authorization requests
exactly `channels:read`, `chat:write` and `groups:read`; `src/slack-oauth.ts` and
its tests own that contract. Slack's generic Add to Slack URL uses the broader
internal app scope set and must not replace the hosted customer flow.

Bot tokens are exchanged server-side and persisted through the authorized
completion RPC. Keep credentials, signed response URLs and invitation links out
of source control. Distribution state is maintained separately in the Slack
console and cannot be inferred from this manifest.

Current notification routing and delivery belong to the
[Notifications & Slack module](https://linear.app/lifty-corp/document/lead-gen-system-notifications-and-slack-a6e52a3fd81f).
The original configuration decisions are in LIF-637 and LIF-639; shared-app
interactivity is covered by LIF-1467. Historical pilot drafts and rollout receipts
remain in Compass Git history and their Linear issues.
